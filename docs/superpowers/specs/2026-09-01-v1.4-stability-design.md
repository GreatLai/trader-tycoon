# v1.4 Stability Design

## Goal

Stabilize v1.4.0 without changing its intended gameplay balance. Fix confirmed correctness, compatibility, and markup defects, then protect them with repeatable automated tests.

## Scope

- Prevent ultra-tier goods from appearing in a fresh game before the 10,000,000 unlock threshold.
- Preserve money when forced liquidation pays a daily-cost shortfall: sold inventory funds the shortfall and only the surplus remains as cash.
- End the run on day 90 without creating or charging a synthetic day 91.
- Migrate active v1.3 ecological-event saves to the compressed v1.4 four-day timeline.
- Restore the intended sibling layout for warehouse, bank, daily costs, and news panels.
- Add zero-dependency Node regression tests for rules, save migration, event data, and a deterministic 90-day simulation.

## Non-Goals

- No event multiplier, warehouse fee, credit, or forced-liquidation balance changes.
- No UI redesign.
- No module-system conversion, framework adoption, or broad refactor.
- No removal of legacy configuration or data files in this pass.

## Architecture

Tests load the classic browser scripts into a Node `vm` context with minimal DOM and storage stubs. This keeps the production delivery format unchanged while allowing deterministic tests of the real game functions.

Save loading gains a small normalization step. Legacy ecological-event progress is mapped by completed branch depth rather than its old relative day, which prevents null branch access and retains the player's current event outcome.

Day-limit handling moves to the start of `nextDay()` when the player is already on the final playable day. Forced-liquidation settlement remains in the economy layer but explicitly subtracts the unpaid daily cost from liquidation proceeds.

## Verification

- Every confirmed defect has a regression test that fails against v1.4.0.
- All JavaScript files pass syntax checks.
- Event-tree validation covers every A/B/C branch and affected good multiplier.
- Deterministic simulations complete without exceptions, non-finite values, negative inventory, capacity overflow, or day 91.
- Browser checks cover intro, market, trade, chart, history, bank actions, panel hierarchy, and mobile layout.
